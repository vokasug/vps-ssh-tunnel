# VPS SSH Tunnel

Нативное macOS-приложение (SwiftUI, без зависимостей) для управления SSH SOCKS5-туннелем к вашему VPS одной кнопкой.

## Какую задачу решает

Обход блокировок и маршрутизация трафика через собственный VPS обычно делается в терминале: запустить `ssh -D`, проверить `curl`, убить `pkill`, перезапустить Chrome с флагом прокси. Приложение заменяет всё это на GUI с кнопками, автовосстановлением туннеля при обрывах и журналом событий.

## Функции

- **Старт (⌘T)** — проверяет туннель и, если он не работает, поднимает SOCKS5-прокси: `ssh -D <порт> -N -f` с keepalive-параметрами. После запуска автоматически проверяет результат.
- **Проверка** — проверяет туннель запросом к `https://api.telegram.org` через SOCKS5 (ожидаемый код 302).
- **Стоп** — останавливает туннель, если он запущен.
- **Telegram (⌘G)** — если Telegram уже запущен, предлагает закрыть его; затем проверяет/поднимает туннель и запускает `/Applications/Telegram.app` (прокси в Telegram настраивается один раз: SOCKS5, `127.0.0.1`, ваш порт).
- **Chrome (⌘B)** — если Chrome уже запущен, предлагает закрыть его; затем проверяет/поднимает туннель и запускает Chrome с `--proxy-server="socks5://127.0.0.1:<порт>"`.
- **Восстанавливать при обрыве** — каждые 10 секунд проверяет туннель; при обрыве перезапускает. Если перезапуск не удался (нет сети, VPS недоступен), попытка повторяется при каждой следующей проверке, пока туннель не поднимется или галка не будет снята вручную. При выключении экрана мониторинг приостанавливается (с записью в лог), при включении — возобновляется с мгновенной проверкой туннеля (через `NSWorkspace.screensDidSleep/DidWakeNotification`).
- **Лог** — все события с таймкодами, текст можно выделять и копировать; кнопка «Копировать весь лог» копирует всё в буфер. Лог также пишется в файл `~/.config/vps-ssh-tunnel/vps-ssh-tunnel.log` (обнуляется при каждом запуске).
- При закрытии приложения работающий туннель автоматически завершается.

## Настройки

Поля «Сервер» (user@host или алиас из `~/.ssh/config`), «Локальный порт» (SOCKS5) и «SSH порт» вместе с состоянием галки автоматически сохраняются в `~/.config/vps-ssh-tunnel/.vps-ssh-tunnel` (JSON) и подгружаются при запуске. Файл и папка создаются автоматически при первом запуске.

## Требования

- macOS 13+
- SSH-доступ к VPS по ключу (парольный вход не используется — `BatchMode=yes`). Настройка:
  ```bash
  ssh-keygen -t ed25519
  ssh-copy-id user@your-server
  ssh -o BatchMode=yes user@your-server true   # должно завершиться молча
  ```
- Для кнопок Telegram/Chrome — установленные приложения.

## Установка

### Готовое приложение из релиза

1. Скачайте `VPS-SSH-Tunnel.app.zip` из [раздела Releases](../../releases), распакуйте.
2. Приложение не подписано Developer ID, поэтому при первом запуске macOS заблокирует его (диалог «Переместить в корзину» / «Готово» — нажмите «Готово»). Далее разблокируйте одним из способов:
   - **Системные настройки → Конфиденциальность и безопасность** → сразу после заблокированной попытки внизу появится «VPS SSH Tunnel заблокировано» → нажмите «**Всё равно разрешить**» и подтвердите (рекомендуется);
   - или через терминал, сняв карантин: `xattr -dr com.apple.quarantine "VPS SSH Tunnel.app"`.
3. Переместите в `/Applications` (необязательно) и запустите.

### Сборка из исходников

Нужны только Xcode Command Line Tools (`xcode-select --install`):

```bash
git clone https://github.com/vokasug/vps-ssh-tunnel.git
cd vps-ssh-tunnel
./make-app.sh
open "dist/VPS SSH Tunnel.app"
```

## Как работает туннель

`ssh -D` поднимает локальный SOCKS5-прокси: весь TCP-трафик, направленный на `127.0.0.1:<порт>`, уходит через зашифрованное SSH-соединение на VPS и выходит в интернет уже с него (включая DNS при использовании SOCKS5 с удалённым резолвом). Keepalive-параметры (`ServerAliveInterval=30`, `ServerAliveCountMax=3`, `TCPKeepAlive=no`) гарантируют, что мёртвая после сна или обрыва сессия завершится сама, а галка автовосстановления поднимет туннель заново.

Для консольных утилит без собственной поддержки прокси удобно использовать `proxychains-ng` (`brew install proxychains-ng`, в конфиге указать `socks5 127.0.0.1 <порт>`): `proxychains4 <команда>`.

## Разработка

Нативное приложение: SwiftUI, SwiftPM executable target, без внешних зависимостей (только Foundation/AppKit/SwiftUI), macOS 13+.

### Сборка и запуск

- `swift build` — отладочная сборка (быстрая проверка компиляции).
- `./make-app.sh` — release-сборка и сборка `dist/VPS SSH Tunnel.app` (бинарь, Info.plist, иконка, ad-hoc подпись).
- `swift scripts/generate-icon.swift Resources && iconutil -c icns Resources/AppIcon.iconset -o Resources/AppIcon.icns` — перегенерация иконки (тёмный скруглённый квадрат с бирюзовыми кольцами, рисуется программно, графических ассетов нет).
- Тестов нет. Проверка изменений — сборка и, для изменений UI/поведения, запуск приложения (`open "dist/VPS SSH Tunnel.app"`) и нажатие кнопок; основные артефакты проверки — лог-файл и скриншот окна.

### Структура

- `Package.swift` — единственный executable target `VpsSshTunnel`.
- `Sources/VpsSshTunnel/VpsSshTunnelApp.swift` — `@main`, WindowGroup, AppDelegate (завершает приложение при закрытии последнего окна).
- `Sources/VpsSshTunnel/ContentView.swift` — UI: поля сервера/портов, кнопки, галка автовосстановления, лог. Наблюдает `AppState` и `LogStore`.
- `Sources/VpsSshTunnel/AppState.swift` — вся логика действий (Старт/Проверка/Стоп/Telegram/Chrome), монитор автовосстановления, пауза мониторинга при сне экрана, сохранение настроек, хук завершения.
- `Sources/VpsSshTunnel/TunnelManager.swift` — обёртки `Process` для ssh/curl/pkill/open, проверки запущенности приложений.
- `Sources/VpsSshTunnel/SettingsStore.swift` — JSON-конфиг `~/.config/vps-ssh-tunnel/.vps-ssh-tunnel`, создаётся с дефолтами автоматически.
- `Sources/VpsSshTunnel/LogStore.swift` — лог в памяти + зеркало в файл `~/.config/vps-ssh-tunnel/vps-ssh-tunnel.log` (обнуляется при запуске).

### Соглашения и подводные камни

- Язык UI и лога — русский. Сообщения коммитов — английский.
- Без комментариев в коде, если не попросили. Без новых зависимостей.
- Формат лога: `[HH:mm:ss] сообщение`, одна строка на событие, без пустых строк. 10-секундный монитор молчит, пока туннель здоров, — пишет только об обрывах/перезапусках.
- `ContentView` должен наблюдать `LogStore` напрямую (`@ObservedObject` через кастомный init). Вложенный `ObservableObject` внутри `AppState` сам по себе НЕ инвалидирует view — из-за этого однажды асинхронные строки лога не отрисовывались.
- Никогда не обращаться к wrapped value `@StateObject` в `init` App-структуры — создаётся дублирующий экземпляр. Поэтому обработка завершения сделана через `NSApplication.willTerminateNotification` внутри `AppState`.
- Мутации `Settings` сохраняются через didSet с guard'ом `lastSaved` — writeback SwiftUI может вызвать didSet с неизменёнными значениями; guard не удалять.
- Все действия кнопок защищены `actionBusy` (реентерабельность) — guard сохранять и сбрасывать на каждом пути асинхронного завершения.
- Цепочка перезапуска монитора перепроверяет `monitorTimer != nil` после асинхронных шагов и откатывает перезапущенный туннель, если пользователь нажал Стоп (или погас экран) посреди перезапуска. Сохранять это при редактировании.
- `pkill -f "ssh -D <порт>"` матчит любой процесс, чья командная строка содержит паттерн, — включая собственные shell-команды агента. В скриптах/тестах использовать трюк со скобкой: `pkill -f "ssh -D 108[0]"`.
- ssh вызывается с `-o ConnectTimeout=5`, чтобы недоступные хосты быстро фейлились; проверка curl использует `--max-time 10` и ждёт HTTP 302 от api.telegram.org.
- Конфиг никогда не должен хардкодить реальный сервер пользователя; дефолт — `root@1.1.1.1`.
